# Sparkz v1 scope (two-track: ship a floor, keep innovating)

V1 is the FLOOR, not the ceiling. Two parallel tracks so we hit neither failure mode (endless architecture that never ships, or shipping something obsolete on arrival):

- **SHIP TRACK** - build and prove ONE complete loop (Zoostr).
- **INNOVATION TRACK** - continuously design and prototype the larger Sparkz system.

## The north star (Hearth-first)

Every Sparkz project begins as a **Hearth**, not a coin. The coin is an optional output. The Hearth accumulates identity, contributors, history, content and code, supporters, free boosts, and economic config. A **Spark** is an event on a Hearth (a moment, a token, an NFT drop, a bounty, an event), ideally something onchain we can point to. Back the album, not a coin.

Entry points (the schema supports all; v1 builds one):
1. **Creator** - a person plus their work, audience, and collaborators.
2. **Culture** - a community, movement, scene, or event.
3. **Open-Source Project** - repos, contributors, maintainers, dependencies. Build ABOVE Drips (which already routes onchain money to maintainers and dependencies), do not recreate it.

## What ships in v1 (the honest floor)

Zoostr, as a Creator Hearth:
- **Zoostr Creator Hearth** with pre-token backing (no token required).
- **Free boosts**, no wallet needed to start.
- **Sparks** - events lit on a Hearth by its owner.
- **1/1/98 creator-first economics** and a 0xSplits distribution wallet if and when a token launches (Clanker adapter).
- **FEF (Farcaster Eats First)** as a protocol rule: first announcements and first backing windows go to Farcaster first.
- Swappable adapter seams (`BackingProvider`, `Connector`) so rails and vendor tools can be added without a rewrite.

## Product gates (the proof sequence)

- **Gate 1** - Can Zoostr create active backers? (v1)
- **Gate 2** - Can Sparks give people something to do onchain? (v1)
- **Gate 3** - Can the same machinery work for ZAOstock? (v1.5)
- **Gate 4** - Can it work for an open-source repository? (v1.5, the OSS entry point)

## Anti-failure gate (every proposed feature must pass all 4, or it stays in the lab)

1. Does it help someone earn, participate, or distribute?
2. Can we measure whether it worked?
3. Does it strengthen the Hearth's data?
4. Can it be tested with a real project within 30 days?

## Deferred (INNOVATION track, NOT v1)

- **Contribution Graphs** full build - track code, reviews, docs, issues, design, distribution, and revenue with evidence and weighting; propose sponsorship splits, bounties, and allocations. v1.5, on the Drips primitive.
- **Culture Health Dashboard** - contributor, retention, and participation metrics independent of token price. v1.5.
- **Culture launcher** (governance and treasury) - after the legal wrapper.
