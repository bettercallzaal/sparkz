# Sparkz today (as read 12 Nov 2026)

Surface read: repo checkout at `scratchpad/wt-sparkz` (HEAD dff6e0f "ios: Capacitor iOS project for the TestFlight build"), plus a WebFetch of https://trysparkz.com. All paths below are relative to that checkout.

## Core objects

- **Hearth** - the project home. One DB table (`hearths`, renamed from `capsules` in `supabase/migrations/0005_rename_capsule_to_hearth.sql`). Holds name, bio, type (creator / culture / oss / meme), status (lit / dormant), Farcaster identity, links, tags, economic config, review state (pending / approved). Public page at `/c/[slug]`.
- **Backer / Boost** - `hearth_backers` rows. A boost is a free support signal, one per backer per Hearth (`src/app/api/boost/route.ts`).
- **Meme Receipt** - proof-of-contribution post generated by the Meme Engine (`meme_receipts`).
- **Spark** - [Certain, from `supabase/migrations/*` which create only capsules/hearths, capsule_backers, signals, signal_drafts, meme_receipts, waitlist, capsule_plugins, team_signups] a Spark is NOT a database object. It is a concept in copy: "any event that grows the Hearth: a show, a drop, a release, a collab, a launch" (`README.md`). The Hearth page has no "Sparks" section and there is no "create a Spark" action inside a Hearth.
- **Naming collision** - the thing a user creates at `/start` is a Hearth, but the button and API are called "Light your spark" / `/api/capsules/create-spark` (`src/app/_components/StartForm.tsx`). `/profile` lists "Your sparks" which are Hearths (`src/app/_components/YourSparks.tsx`). So in the UI today "spark" means Hearth, while the README and `/hearth` page say Spark means event. This is the single biggest conceptual problem for daily use.

## Navigation today

- **No tab bar anywhere.** [Certain: grep of `src/app/layout.tsx` and `_components` found only `Header`, `MobileNav`, `Footer`.]
- Root layout (`src/app/layout.tsx`) wraps every page in a sticky `Header` and a large `Footer`.
- `Header.tsx`: flame + wordmark, inline nav `Explore / How it works / Blog / Architecture` that is `hidden sm:flex` (so absent on iPhone), an "Add mini app" button, `HeaderAuth`, a gold "Try Sparkz" CTA (always to `/start`), and `MobileNav`.
- `MobileNav.tsx`: hamburger drop-down with Explore, Light a spark, How it works, Blog, Architecture, Sign in with Farcaster. Four of six items are marketing pages.
- `HeaderAuth.tsx`: signed-out "Sign in" link is `hidden ... sm:inline`, so on an iPhone there is no visible sign-in in the header at all; only the hamburger holds it. Signed in: a 24px avatar pill linking to `/profile`.
- `Footer.tsx`: 20+ links in three groups, a "Discord - soon" label, an "Operator" link. About 300px of footer on a phone, on every page.

## Onboarding for a new user

1. Land on `/` (a marketing page). The only conversion is a waitlist email form, or the header "Try Sparkz".
2. `/start`: 4 fields including email. No sign-in. Hearth is created and owned by an email address, with `owner_fid` unset (`StartForm.tsx` sends no `owner_fid`).
3. Or `/profile`: Sign in with Farcaster, then fill the second Hearth form there (`CreateSparkAsFarcaster.tsx`), which does attach `owner_fid`.
4. Two different create paths with different ownership semantics. A phone user does not know which to pick.
5. Private alpha: `src/lib/alpha-access.ts` sets `ALPHA_LOCK = true`; only admin identities and FID 1057869 (IMan) can sign in, and `/api/boost` returns 403 without a session. So today only Zaal and IMan can use it at all (live alpha, commit 62c2e7a).

## What a returning daily user does today

There is no daily loop in the product. Zaal opens the app, lands on the marketing home, has to find `/profile` (avatar or hamburger), taps into one of "Your sparks", reads a Hearth page. Nothing says what changed since last time. No notifications, no "new backers", no pending-review count, no activity feed for his own Hearths. `ActivityStrip` on the home is public/global, not personal. Owner actions (settings, visibility, approving Meme Engine drafts) have no entry point from the Hearth page that I could find.

## Web-first things that are awkward in an iPhone shell

Shell facts from `capacitor.config.ts`: WebView loading `https://trysparkz.com`, `contentInset: "always"`, safe-area padding on `body` (`globals.css` lines 64-69). Per `docs/TESTFLIGHT.md` Apple guideline 4.2 is a known later risk. I fetched the guideline: 4.2 says an app "should include features, content, and UI that elevate it beyond a repackaged website" (https://developer.apple.com/app-store/review/guidelines/).

1. **Marketing page as the app's first screen.** `/` is a 6-section pitch with a waitlist form. Inside an app the user has already installed, "join the list" is wrong.
2. **Tiny tap targets.** Hamburger is `h-8 w-8` (32px, `MobileNav.tsx`); copy button `h-8 w-8` (`c/[slug]/page.tsx`); share button `py-1.5 text-sm`; link pills `px-3 py-1` text-xs; tag chips `text-[11px]`; avatar pill 24px. Apple's Buttons guidance: "a button needs a hit region of at least 44x44 pt" (https://developer.apple.com/design/human-interface-guidelines/buttons, fetched via the developer.apple.com tutorials JSON endpoint).
3. **Hover-only affordances.** `hover:text-foreground`, `hover:border-accent`, `glass-hover`, `.btn-spark:hover` sheen are everywhere; no pressed state is defined that I found (grep of `globals.css` for `active:` was not run; treat as unverified).
4. **Desktop nav.** Inline nav is hidden on phones, leaving a hamburger holding mostly marketing links. Primary actions (your Hearths, create, explore) are two taps deep.
5. **Sticky 56px header plus safe-area `padding-top` on `body`.** Header is sticky inside a body that is already padded, so on a notched iPhone the sticky header sits below a padded gap and scrolls content under a translucent bar; worth verifying on device (unverified, inferred from `layout.tsx` + `globals.css`).
6. **Footer on every page.** A 20-link site footer inside an app is dead weight and pushes the home indicator area.
7. **Forms ask for what the app already knows.** `BoostForm.tsx` asks "your email or handle" even when signed in. `StartForm.tsx` asks email while `/profile` form does not.
8. **Dropdown `<select>` for Hearth type** with long labels (`StartForm.tsx`), `autoFocus` on name opens the keyboard immediately on `/start`.
9. **External links leave the app.** Farcaster/website/GitHub pills use `target="_blank"`; the config says non-allowed hosts open in Safari, so those bounce the user out with no way back except app switching.
10. **Emoji in copy** in `/hearth` and `fc:frame` buttons. House style says none; not a phone issue but worth cleaning in the same pass.
11. **No pull-to-refresh or loading states** on `force-dynamic` server pages; every navigation is a full network round trip from Zambia or the US with no skeleton (inferred from `dynamic = "force-dynamic"` in `page.tsx`, `c/[slug]/page.tsx`).
